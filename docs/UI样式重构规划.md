## 1. 现状诊断

当前 UI 全部集中在 `crates/gt-ui/ui/main-window.slint`（约 3290 行），功能已齐但样式债集中体现在四类问题：

| #   | 问题                       | 具体表现                                                                                         | 后果                   |
| --- | ------------------------ | -------------------------------------------------------------------------------------------- | -------------------- |
| D-1 | **单文件巨型化**             | 主题、13 个数据 struct、10+ 个子组件、主窗口、8 个遮罩/对话框全在一个文件里                                      | 无法定位、无法复用、改动牵一发动全身 |
| D-2 | **设计 token 缺失/被绕过**      | `Palette` 里已有语义色，但组件内部仍散落硬编码色值（如选中态 `#35507a`/`#cfe0ff` 写死在 LogRowView、ChangeRowView 两处；禁用态 `#33353a` 写死在 FlatButton） | 主题切换遗漏、明暗两套不保证一致     |
| D-3 | **无字号/间距/圆角规范**          | 字号 10/11/12/13/15px 随手写；padding 4/6/8/10/14px 混用；圆角 0 或 3px 不统一                             | 观感杂乱、"不整洁"的直接来源      |
| D-4 | **固定像素列宽 → 错位**          | Log 行（62/150/120/130px）、Change 行（120/26/150px）、Stash 行（86px + `parent.width - 380px` 这类算术）全部写死   | 窄窗口挤压、溢出、错位——正是 M4 遗留走查项 |
| D-5 | **控件形态不统一、信息密度低**        | 顶栏 8 个同级 FlatButton 一字排开；侧栏 8 个文字按钮两行堆叠；无图标、无分组、无分隔线                                          | 与 IDEA 工具窗观感差距大      |

**有利条件**：三条渲染纪律（虚拟化、自绘泳道、分段文本）与 Rust 侧接线（`view_model.rs` / `session.rs` 的回调与 struct）都是健康的，本次重构**只动 .slint 表现层，不动数据契约**，回归风险天然很低。

## 2. 阶段建议：插入「M4.5 UI 专项」，在 M5 开始前实施

### 结论

**建议作为独立小阶段 M4.5（1.5–2 pw）插在 M4 → M5 之间，即"现在就做"。** 理由：

1. **M4 遗留项本来就卡在这里。** M4 验收报告明确"窄窗口下三路编辑器与变基编辑器的观感未验证，M5 首轮人工走查时一并确认"。错位修复（D-4）与这次走查是同一件事的两面，先修再走查，避免走查两遍。
2. **M5 会新增一批视图，重构必须赶在它们之前。** M5 要交付 Blame 视图、图片 Diff、安装包启动页/引导页——如果先写新视图再重构，新视图会带着旧样式债落地，返工量翻倍；先立好 token 与组件库，新视图直接复用，成本最低。
3. **M5 估时已满（5 pw），塞不下 1.5 pw 的样式重构**，硬塞会挤掉内存回归 CI（5-5）这类发布硬门槛。
4. **风险最低的窗口期。** M4 刚收尾、功能冻结，重构纯动 .slint 不动回调签名，不会和任何在途功能冲突。

### 备选方案（如想尽快出 v1.0）

若 v1.0 时间优先，可降级为 **M4.5-lite（0.5 pw）**：只做 S1（token 提取）+ S4 中的错位修复与窄窗口走查，文件拆分与 IDEA 观感对齐推迟到 v1.1。两条路线共用下文第 3 节的步骤划分，只是裁剪范围不同。

### 路线图位置

```
M4 ──→ ★M4.5 UI专项 ──→ M5 打磨与发布 ──→ G5 → v1.0
(已完成)   1.5–2pw          (5pw)
        ├ S1 tokens ─┐
        ├ S2 组件库   ├─ 新视图（Blame/图片Diff/引导页）直接复用
        ├ S3 拆文件 ─┘
        └ S4 布局对齐IDEA + 窄窗口走查（消化M4遗留A项）
```

## 3. 重构方案（四步纵切，每步可独立提交、独立验收）

### S1 设计 token：`theme.slint`（0.25 pw）

把 `Palette` 扩充为完整 token 表，作为唯一取色/取值来源，**禁止组件内再出现裸色值**（用 clippy 式纪律：review 时 grep `#[0-9a-f]{6}`）。

- **配色对齐 IDEA New UI**：现暗色底 `#1e1f22` 已与 JetBrains New UI Dark 一致，主要补齐：
  - 语义选中色：统一为 accent 系（IDEA 用 `#3574F0`/dark `#365880` 一族），替换散落的 `#35507a`/`#cfe0ff`；
  - 状态色语义化：success / warning / danger / info 各配 bg / text / border 三档；
  - diff 色对齐 IDEA：add `#2EA043`-系底色、del `#F85149`-系底色（明暗各一套）。
- **字号阶梯**：`font-xs: 11px / font-sm: 12px / font-md: 13px`，标题用字重区分而非加大字号（IDEA 做法）。
- **间距阶梯**：4 / 8 / 12 / 16px；**圆角**统一 4px（IDEA New UI 规范值）；行高：log 26px、diff 18px、列表 24px 收进 `Metrics`。

### S2 基础组件库：`widgets.slint`（0.5 pw）

把现有子组件升级为统一控件并补齐形态：

| 现有            | 升级为                    | 补齐的形态                            |
| -------------- | ------------------------ | ------------------------------------ |
| FlatButton     | `IdeaButton`            | primary / secondary / danger / **ghost**（顶栏与行内按钮改为 ghost，去边框，hover 才有底色——IDEA 工具栏按钮的做法） |
| TabButton      | `IdeaTab`               | 下划线选中 + hover 过渡                |
| Field          | `IdeaInput`             | 聚焦态描边（accent 色）、占位符色 token     |
| OptionToggle   | `IdeaChip`              | 选中态用 accent 底 + 白字，未选中 ghost    |
| CtxMenuItem    | `MenuItem` + `Menu`     | 分隔线、危险项红字、快捷键右对齐槽位        |
| （新增）          | `SectionHeader` / `Divider` / `Badge`（refs 胶囊、状态徽标） | |

### S3 文件拆分（0.25 pw，可与 S2 并行）

> **实施记录（2026-10-17）**：按"零重接线"边界落地为六个文件——
> `theme.slint`（token）/ `model.slint`（15 个 struct 原样迁出并再导出）/
> `widgets.slint`（组件库）/ `rows.slint`（四个列表行）/ `dialogs.slint`
> （九个浮层，收口为显式接口组件 + DialogShell 统一骨架）/
> `main-window.slint`（3290 → 1574 行）。与原方案的差异：**panels 未继续下拆**——
> 主体的 Log/Diff/底部面板与近 90 个窗口属性/回调深度耦合，下拆需要镜像
> 整套接线，风险收益不成比例；待 M5 新视图（Blame 等）落地后再按需抽取。

```
crates/gt-ui/ui/
├── theme.slint          // Palette/Metrics（S1 产物，全局单例，唯一裸色值处）
├── model.slint          // 15 个 export struct 原样迁出（字段不改名）
├── widgets.slint        // S2 基础组件（Idea* 新控件 + 历史别名子类）
├── rows.slint           // LogRowView / DiffRowView / ChangeRowView / ConsoleRowView
├── dialogs.slint        // 九个浮层：确认/设置/推送/远端/菜单/操作/变基/冲突/比较
└── main-window.slint    // 窗口属性与回调契约 + 主体布局 + 浮层实例化
```

**硬约束（已验证）**：`export struct` 的名字与字段不变，`MainWindow` 的
回调签名与属性集不变 → Rust 侧（`view_model.rs`/`session.rs`/`app/windows.rs`
的 `on_*` 契约表与 `get_set_*` 读取）**零改动**；build.rs 编译入口不变，
Slint 沿 import 树自动加载多文件。

### S4 布局对齐 IDEA Git 工具窗 + 错位修复（0.5–1 pw）

1. **列宽全部改为弹性行为**：固定 px → `min-width + horizontal-stretch + elide`；删除 `parent.width - 380px` 这类算术定位（Stash 行改 HorizontalLayout）。列宽策略写进 widgets 注释。
2. **顶栏重构**（对齐 IDEA VCS 工具栏）：Fetch / Update / Push 保留为 ghost 按钮 + 分组分隔线；「远端 / 设置 / 刷新」收进右侧 ⋯ 溢出菜单或齿轮图标；分支信息做成 IDEA 式分支 widget（当前分支 + ahead/behind 徽标 + 点击弹分支列表，替代左栏常驻）。
3. **侧栏瘦身**：8 个文字按钮 → 选中分支后出现上下文操作（＋ 新建 / 检出 / ⋯），低频动作（删标签、分离检出）进右键菜单——菜单组件 S2 已备好。
4. **Log 行对齐 IDEA**：refs 渲染成胶囊 Badge（分支绿 / 标签黄 / HEAD 加粗），作者/时间列合并为一列右对齐，减少 4 列变 3 列的拥挤感。
5. **对话框统一**：所有遮罩共用一个 `Dialog` 骨架（标题栏 / 内容槽 / 右下按钮区 / Esc 取消），宽度 min(560px, 80%)，替代目前各自为政的尺寸。
6. **窄窗口走查**（顺带消化 M4 遗留 A）：1024×700 下逐一确认三路编辑器、变基编辑器、推送预览的可读性，问题当场修。

## 5. 风险与纪律

| 风险                          | 缓解                                                                 |
| --------------------------- | ------------------------------------------------------------------ |
| 拆文件时 struct/回调漂移，破坏 Rust 接线  | 硬约束"字段与签名不动"；拆完先编译再动样式，两步分开提交                        |
| 重构破坏三条渲染纪律（虚拟化/自绘泳道/分段文本）    | ListView 结构不动，只改行内布局；泳道绘制代码（GraphCell 渲染）原样搬运           |
| 主题切换回归（多窗口共享 Palette 语义）     | 每步验收必须含 dark/light 切换 + 双窗口截图对比                          |
| IDEA 样式"像素级复刻"陷入无限打磨          | 明确目标为"形似"：分组、ghost 按钮、胶囊 refs、统一圆角间距即可，不逐像素对照；细节让位 G5 发布评审 |
| 范围蔓延（顺手改交互逻辑）               | 本专项只动表现层；任何交互行为变化（如分支 widget 点击弹列表）单独立项记入 M5 或 v1.1 backlog  |

**验收纪律**：S1–S4 各一个 commit；每步结束 `cargo build` + 启动冒烟 + 明暗主题截图；S4 结束跑一遍 M4 走查清单并在验收报告补记"遗留 A 项关闭"。

## 7. 追加：IDEA Git 双工具窗复刻（2026-10-18）

S1–S4 的 token / 组件 / 图标地基完成后，按本机 IDEA 2025.1.7.2 New UI 截图继续实施了 P1–P4：

- **P1 视觉地基**：从 `app-client.jar` 的 expUI 主题 JSON 提取明暗双色板；引入 Apache 2.0 的 IDEA expui 图标；
- **P2 提交工具窗**：已暂存 / 未暂存分组、批量暂存/反暂存、修订 / 保留作者、提交与提交并推送；
- **P3 Git 日志**：分支树（HEAD / 本地 / 远程 / 标签分组、可折叠）、提交行 refs 徽标（最多 2 个 + `+N`）、当前分支底色、提交详情与文件历史差异；
- **P4 打磨**：窄窗口响应式（提交面板 320、详情栏按宽度隐藏、行内列收窄）、浅色主题、i18n 扫描与 clippy / 测试全量回归。
