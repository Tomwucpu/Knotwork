## 1. 文档说明

### 1.1 需求编号与优先级规则

- 需求编号：`FR-<模块>-<序号>`，非功能需求编号 `NFR-<序号>`。
- 优先级定义：
  - **P0**：v1.0 必须交付，缺失即视为产品不成立；
  - **P1**：v1.0 应交付，缺失会显著降低可用性，但可在一个补丁周期内补齐；
  - **P2**：增强项，可随里程碑顺延，不承诺 v1.0 交付。
- 每条需求附**里程碑归属**（M0–M6，定义见架构规划第 8 节）与**验收标准**（可测试的客观表述）。

### 1.2 术语约定

| 术语 | 含义 |
|---|---|
| 仓库窗口 | 绑定一个 Git 仓库的独立应用窗口 |
| 暂存 / Staging | `git add` 语义的本地暂存区操作 |
| hunk | diff 中的一个连续变更块 |
| 泳道图 | 提交历史的有向无环图渲染，每个分支一条纵向泳道 |
| 三路合并 | base / ours / theirs 三方输入的冲突解决编辑器 |
| 只读降级 | 检测到写风险（他进程持有写锁、操作半途失败）时，窗口进入禁止写入的保护模式 |

## 2. 产品定位与设计原则

### 2.1 定位

对齐 IntelliJ IDEA Git 工具窗口功能的**独立轻量 Git 客户端**，核心卖点：极低内存占用（空闲 < 40MB）、多窗口并行管理多个仓库、行为与 git 命令行完全一致。

### 2.2 设计原则（约束所有功能设计）

1. **UI 永不阻塞**：任何 Git 操作不得冻结 UI 线程；耗时操作必须可取消，用户切换上下文后旧结果必须作废不串扰。
2. **命令可审计**：工具执行的每一条底层 git 命令与语义操作，用户可在 Console 面板中查看（见 FR-CON-01）。
3. **写操作可回退 / 可中止**：所有写操作提供明确的 abort / continue 路径提示（rebase 中断后必须引导用户到 `--continue` / `--abort`），不允许留下"半完成状态"且无提示。
4. **与 CLI 行为一致**：status / diff / log 的输出语义以 `git` 命令行为为真相标准，任何偏差视为 P0 缺陷（架构规划 7.1）。
5. **内存是硬约束**：任何功能不得以"常驻大缓存"换取开发便利；超出缓存预算的行为按 LRU 淘汰。

### 2.3 明确不做（继承架构规划 6 节与匹配分析结论）

| 不做项 | 理由 |
|---|---|
| Changelists / Shelf | IDEA 私有概念，非 Git 标准；staging 模式已覆盖核心诉求 |
| 编辑器 gutter 注解 / Local History | 依赖 IDE 宿主，独立客户端无意义 |
| GitHub/GitLab PR/MR 面板、Issue 导航 | 延后 M6 插件化 |
| 提交签名 UI（GPG/SSH） | v1.0 透传 CLI 行为（用户已配置的 commit.gpgsign 生效即可），UI 化延后 |

## 5. 详细功能需求

### 5.1 仓库与窗口管理（FR-MR）

**FR-MR-01 打开仓库（P0 / M1）**
- 通过"打开"对话框选择本地路径，或拖拽文件夹到窗口；校验该路径是否为有效 Git 仓库（含 worktree 检测）。
- 无效路径给出明确错误（"不是 Git 仓库根 / .git 缺失"），支持 `.git` 文件（worktree/submodule 链接）。
- 验收：打开含子模块与 worktree 的仓库均可正确识别根。

**FR-MR-02 最近仓库列表（P1 / M1）**
- 记录最近打开的仓库（路径、别名、最近打开时间），启动页与 File 菜单可一键重开；列表持久化于用户配置。
- 验收：重开时若路径已不存在或不再是仓库，给出提示且不崩溃。

**FR-MR-03 多窗口多仓库（P0 / M1）**
- 每个仓库一个独立窗口；窗口标题显示 `仓库名 (分支名)`；同一仓库不允许重复多开（见 FR-MR-04）。
- 关闭窗口即释放该仓库的全部视图状态与缓存分区。
- 验收：3 窗口打开 3 个不同仓库时总 RSS < 90MB（对应 NFR-MEM-02）；关闭其中一个后其内存分区被回收。

**FR-MR-04 仓库写锁与只读打开（P0 / M2）**
- 打开仓库时尝试获取 `.git/<tool>.lock`（存 PID）。获取失败时窗口以**只读模式**打开并在显著位置提示"仓库正被其他实例（PID xxx）写入"。
- 只读模式下所有写操作按钮禁用，并显示统一的原因。
- 验收：两个实例打开同一仓库，后开的为只读；前者退出后重开可恢复读写。

**FR-MR-05 单实例守卫（P1 / M2）**
- 默认单进程多窗口；再次启动可执行文件时把新开请求交给已运行实例（IPC），而非起第二个进程。`--isolate` 参数启动隔离进程（架构规划 4.2），用于极端场景。
- 验收：双击打开第二个仓库路径时，由已有进程弹出新窗口，进程数不变。

### 5.2 Local Changes —— 本地更改视图（FR-LC）

**FR-LC-01 更改列表（P0 / M1 只读 / M2 可写）**
- 视图分为三个分区：**Unversioned**（未跟踪）、**Modified**（已修改未暂存）、**Staged**（已暂存）；文件按目录树或平铺展示（可切换）。
- 数据源为后台增量状态计算（gix-status），文件系统变更经 200–300ms 去抖后自动刷新（对应 FR-STA-03）。
- 验收：状态判定与 `git status --porcelain=v1` 输出一致（一致性测试用例 LC-01）；`git checkout` / `git add` 等外部命令引起的变化在 1s 内反映到界面。

**FR-LC-02 文件级暂存 / 反暂存 / 丢弃（P0 / M2）**
- 单文件与多选：暂存（add）、反暂存（restore --staged）、删除未跟踪文件（可选入回收站或永久删除，需二次确认）、丢弃已跟踪文件的修改（**高危操作，需输入确认或显式勾选**，因为不可逆）。
- 验收：操作后状态与 CLI 等价；丢弃修改有二次确认与结果反馈。

**FR-LC-03 hunk 级与行级暂存（P0 / M2）**
- 在 Diff 视图中选中一个 hunk 可单独暂存 / 反暂存 / 丢弃；行级选择：按住拖选多行后可只暂存所选行（`git apply --cached` 语义）。
- 验收：对同一文件"先暂存 hunk A、丢弃 hunk B、行级暂存 hunk C 的部分行"后，`git diff --cached` 结果与用户操作意图一致。

**FR-LC-04 忽略规则（P1 / M2）**
- 未跟踪文件右键"加入 .gitignore"，可追加到根 `.gitignore` / `.git/info/exclude` / `.ignore`，支持目录前缀模式。
- 验收：追加后该文件移出 Unversioned 分区；`git check-ignore` 验证规则生效。

### 5.3 提交（FR-CMT）

**FR-CMT-01 提交流程（P0 / M2）**
- 提交面板：已暂存文件列表（可在此反暂存）、提交消息多行编辑（支持模板：含作者、分支、最近消息记忆）、Commit 按钮。
- 提交后 Local Changes 刷新，Console 面板显示实际执行的命令。
- 验收：提交结果与 `git commit` 等价（作者、日期、树内容、消息编码 UTF-8）。

**FR-CMT-02 Amend（P0 / M2）**
- "修订上次提交"入口：复用上一条提交的消息与暂存内容，默认勾选"保留作者信息"（--reset-author 可选）。
- 验收：amend 后 `git log -1` 的消息/作者符合选项组合。

**FR-CMT-03 提交前检查（P1 / M2）**
- 提交前可选执行：消息非空校验、警告配置（CRLF 即将提交、detached HEAD 提交、rebase 进行中提交）——对齐 IDEA 设置项（调研 1.3）。
- hooks 由 git CLI 路径天然执行；hooks 失败时展示 stdout/stderr 且不提交。
- 验收：构造 pre-commit 失败场景，UI 显示失败输出并阻止提交。

### 5.4 Log —— 提交历史与泳道图（FR-LOG）

**FR-LOG-01 提交列表与泳道图（P0 / M1）**
- 列表每行：泳道图（含合并/分叉曲线）、缩略哈希、提交消息首行、作者、相对时间；虚拟化渲染，滚动到 100 万条提交不掉帧。
- 分页增量加载（随滚动向下取更多提交），已加载布局增量推进，不因分页触发全图重排。
- 验收：Linux 内核仓库滚动 100 万条，帧时间 P95 < 33ms 且内存无持续增长（M0 验收项 ②）。

**FR-LOG-02 筛选器组（P0 / M1）**
- 分支筛选（默认：本地分支 + 当前跟踪分支；"全部本地与远程分支"为显式选项——对应架构规划决策点 #4）、作者筛选、日期筛选、路径筛选。
- 筛选条件变更 = 新请求代次，旧请求结果作废（架构规划 4.3）。
- 验收：各筛选器与对应 `git log` 参数化输出一致；筛选切换无错乱结果。

**FR-LOG-03 提交消息全文搜索（P0 / M2；大仓库索引 P2 / M5）**
- 搜索框支持片段、完整哈希、正则（可切换大小写敏感）。
- 中小仓库（< 10 万提交）：revwalk 实时扫描（gix mmap，实测可接受即通过）。
- 超大仓库：实时搜索超时（> 1.5s）时提示并提供"构建历史索引"选项，索引持久化到磁盘、增量更新（对应匹配分析缺口 2）。
- 验收：10 万提交仓库内输入关键字 → 首个结果 < 800ms；正则模式行为与 `git log --grep` 一致。

**FR-LOG-04 导航（P0 / M1）**
- 跳转到哈希 / 分支 / 标签（模糊匹配输入）；←/→ 在父/子提交间跳转；双击提交展开详情。
- 验收：跳转目标不在当前已加载页时能正确触发远端分页定位。

**FR-LOG-05 图呈现选项（P1 / M2）**
- 排序：按提交日期 / **拓扑排序（IntelliSort：入边提交紧贴合并提交下方）**；显示第一父项；隐藏合并提交；**折叠/展开线性分支**（折叠后虚线显示，可点击单个分支折叠/展开）；长边虚线化。
- 验收（对应匹配分析缺口 4）：切换排序模式或折叠分支 → 布局增量更新 < 50ms，且只重排受影响泳道。

**FR-LOG-06 高亮规则（P2 / M2）**
- 我的提交加粗、合并提交置灰、当前分支提交底色区分。

**FR-LOG-07 提交上下文操作（P0，随能力分阶段解锁）**
- 复制哈希（M1）、检出修订（detached，需警告，M2）、与本地比较（M1）、创建补丁（M4）、Cherry-pick（M4）、Revert（M4）、**Reset 当前分支到此处（soft/mixed/hard 三选一，hard 需高危确认）**（M4）、撤销提交 Undo（M4，走交互式 rebase 路径）。
- 验收：每项操作后仓库状态与对应 CLI 命令等价；危险操作（hard reset、检出丢弃）有显式确认。

**FR-LOG-08 两提交比较 / 历史快照浏览（P1 / M4）**
- 任选两个提交 → 目录级比较列表（复用 FR-DIF-03）；"浏览该版本仓库"：以只读视图打开某提交的树，禁止写操作。
- 验收：快照视图有醒目的"detached 只读浏览"标识，且不影响工作区。

### 5.5 Diff —— 差异查看（FR-DIF）

**FR-DIF-01 文件差异视图（P0 / M1）**
- 并排 / 统一两种模式（可切换）；hunk 分块显示；行内**词级差异**高亮；可切换忽略空白。
- 验收：diff 结果与 `git diff` 一致（一致性测试 DIF-01，含中文名、CRLF、无尾换行文件）；10MB 文本文件显示占位不尝试加载（NFR-MEM）。

**FR-DIF-02 二进制与大文件（P0 / M1）**
- 检测为二进制或单侧 > 2MB：显示"二进制文件 / 文件过大"占位；不计算 diff（架构规划 5.5）。
- 验收：放置超大与二进制文件的仓库，操作与滚动全程无内存尖峰。

**FR-DIF-03 目录级差异（P1 / M2）**
- 比较两个任意修订（提交/分支/工作区）的目录：输出 增加/删除/修改 文件列表，双击进入文件级 diff（对应匹配分析缺口 3）。
- 验收：结果与 `git diff --name-status <A> <B>` 一致；空目录、重命名检测（rename similarity）行为对齐 git。

**FR-DIF-04 图片 Diff（P2 / M5）**
- 常见格式（PNG/JPG）并排与叠加透明度对比。

**FR-DIF-05 Diff 内操作（P0 / M2）**
- 在 Diff 视图中：暂存该 hunk / 反暂存该 hunk / 丢弃该 hunk / 跳转到文件内对应行。

### 5.6 分支与标签（FR-BR）

**FR-BR-01 分支面板（P0 / M2）**
- 列出本地 / 远程 / 标签三组，标注当前分支与跟踪关系（ahead/behind 计数）；支持新建、检出、重命名、删除（当前分支不可删）、跟踪远程分支。
- 验收：ahead/behind 与 `git rev-list --left-right --count` 一致。

**FR-BR-02 分支操作（P0，M2/M4 分阶段）**
- 新建并检出 / 只建不检出（M2）；合并到当前分支、变基到…（M4）；右键"与当前分支比较"（目录 diff，M4）。
- 删除已合并分支直接执行；删除未合并分支高危确认并列出未合并提交。

**FR-BR-03 标签（P1 / M4）**
- 新建轻量/附注标签、删除、检出（detached 警告）。

### 5.7 合并 / 变基 / 拣选（FR-MRG，M4）

**FR-MRG-01 Merge（P0）**：选择分支合并入当前分支，冲突时进入 FR-CFL 流程；no-ff / ff-only 策略可选（默认跟随 git）。
**FR-MRG-02 Rebase（P0）**：当前分支变基到指定分支/提交；中断/冲突时状态明确（"rebase 进行中，第 x/y 个"），提供 continue / skip / abort 三键。
**FR-MRG-03 交互式 Rebase（P0）**：从选中提交启动，列出后续提交可逐条 pick / reword / squash / fixup / drop（对齐 IDEA 能力）；reword 打开消息编辑框；执行过程逐条显示进度，可中止。
- 验收：三种典型序列（squash 合并 WIP、drop 中间提交、reword 消息）操作后 `git log` 结果与手工交互式 rebase 等价。
**FR-MRG-04 Cherry-pick（P0）**：单提交与连续多选；含 `-x` 追加来源行选项。
**FR-MRG-05 Revert（P0）**：单提交与连续多选，生成反向提交。
**FR-MRG-06 Reset（P0）**：soft / mixed / hard 三模式；hard 需高危确认（列出将丢弃的未提交更改计数）。
- 通用验收：以上全部操作**中途失败时必须提示完整恢复路径**（对应 FR-STA-02）；Console 面板记录实际命令。

### 5.8 冲突解决 —— 三路合并编辑器（FR-CFL，M4）

**FR-CFL-01 三路编辑器（P0）**
- 三栏：左（ours）/ 中（结果）/ 右（theirs）；冲突块高亮编号；每个冲突块可：接受左侧、接受右侧、接受双方、手动编辑中心栏；从左右栏点击块内容可插入到结果。
- 全部冲突处理后 → "标记为已解决"，进入 continue 流程（merge commit / rebase --continue）。
**FR-CFL-02 冲突列表导航（P1）**：文件内冲突块上一处/下一处跳转；多文件冲突时侧栏列出全部待解决文件与计数。
**FR-CFL-03 冲突标记解析（P1）**：对已在磁盘上带 `<<<<<<<` 标记的文件，提供"按标记解析"快捷入口（全部取左 / 全部取右 / 全部取双方）。
- 验收：构造文本/换行/重名冲突场景（含 CRLF 与 UTF-8 中文），解决结果与手工编辑预期一致，`git ls-files -u` 清空。

### 5.9 Stash（FR-STH，M4）

**FR-STH-01** 创建（含 untracked 选项）、应用（保留/删除）、弹出、删除、从 stash 创建分支（P1）。列表显示消息、时间、所属提交。
- 验收：与 `git stash push/apply/pop` 等价；pop 冲突时进入 FR-CFL 流程且不丢失 stash。

### 5.10 文件历史与 Blame（FR-BLM，M5）

**FR-BLM-01 文件历史（P1）**：任选文件 → 历史列表（复用 Log 渲染）；选中提交即时 diff 预览；支持按分支过滤该文件历史。
**FR-BLM-02 Blame 视图（P1）**：逐行显示作者、时间、消息首行；点击行跳转该提交详情。
**FR-BLM-03 Blame 链式导航（P2，对应匹配分析缺口 5）**：在某行 blame 结果上"查看此行之前的版本"→ 定位该行来源提交 → 在其父提交上再次 blame 并滚动到对应行，形成上溯链。
- 验收：gix-blame 输出与 `git blame -l` 逐行一致（含重命名跟随）；链式导航最终命中的 (commit, 行号) 与手工 `git blame <parent>~` 追溯一致。

### 5.11 远端同步与凭据（FR-RMT，M3）

**FR-RMT-01 远端管理（P0）**：增删改 remote（URL、名称）；fetch 单个 remote 或全部。
**FR-RMT-02 Pull 策略（P0）**：Update 操作可配置 merge / rebase（对齐 IDEA Update Project 策略设置），记住用户选择。
**FR-RMT-03 Push（P0）**：推送当前分支 / 多分支；显示将被推送的提交列表预览；被拒时提供"update 后重推"引导；force-with-lease 需显式选项；**受保护分支（用户配置正则列表）禁止 force push**。
**FR-RMT-04 凭据（P0）**：完全复用 git CLI credential 协议与系统 credential helper / SSH agent；HTTPS token 可选存入系统密钥链（keyring）；凭据失败给出可操作的错误（403 / 需要二次验证等），明文密码不落盘。
- 验收：对 SSH 与 HTTPS 两种远端完成完整 push/pull 流程；无凭据时错误提示包含远端 URL 与建议动作。
**FR-RMT-05 并发约束（P0）**：同时运行的 git 子进程 ≤ 4；网络操作超时 120s、可取消并真正 kill 进程树。
- 验收：取消一个正在 fetch 的巨型远端后，无残留 git 进程。

### 5.12 补丁（FR-PTC，M4）

**FR-PTC-01** 从提交/工作区更改生成 patch 文件（`format-patch` / `diff` 语义二选一并说明用途差异）；应用 patch（含 --3way 选项），冲突进入 FR-CFL。

### 5.13 Console —— 命令审计面板（FR-CON，M1 起，对应匹配分析缺口 1）

**FR-CON-01 命令日志（P0）**
- 每个仓库窗口附带 Console 面板，滚动展示本窗口执行的全部底层操作：
  - CLI 路径：完整命令行、退出码、耗时；
  - gix / git2 路径：等价的语义命令（如 `git status --porcelain` 对应标注"（内置引擎）"）。
- 环形缓冲（默认 2000 条），可复制单条、导出全部为文本（排障附件）；支持按模块关键字过滤。
- 验收：任意执行 10 个操作（混合 gix 与 CLI 路径），Console 中能逐条对应；导出内容可直接被用户复制到命令行复现。

### 5.14 设置（FR-SET，M2 起持续交付）

**FR-SET-01 设置界面与持久化（P0 / M2）**：TOML 配置 + 可视化设置窗口，即时生效，分仓库覆盖（仓库级 > 全局级）。
**FR-SET-02 必备设置项（P0）**：

| 设置组 | 项 |
|---|---|
| 外观 | 主题（亮/暗/跟随系统）、字体与字号、界面语言（中/英） |
| Git 行为 | staging 模式开关（默认开）、更新策略（merge/rebase）、CRLF 警告开关、detached HEAD 提交警告 |
| 受保护分支 | 正则列表，禁 force push |
| 外部工具 | 外部 diff / merge 工具命令绑定 |
| 缓存 | 内存缓存预算滑条（默认 32MB）与日志索引磁盘预算 |
| 快捷键 | 全命令可自定义快捷键 |
| 诊断 | 日志级别、日志导出、Console 导出入口 |

- 验收：修改主题与缓存预算立即生效无需重启；外部 diff 工具调用后正确以该工具打开。

### 5.15 稳定性与降级行为（FR-STA，用户可见行为，全程）

**FR-STA-01 崩溃隔离（P0）**：单次 Git 操作内部错误只让该操作失败并 toast 提示，窗口与其他仓库不受影响。
**FR-STA-02 中断状态提示（P0）**：启动时检测 merge / rebase / cherry-pick 进行中的仓库 → 横幅提示并提供 continue / abort 操作入口；任何写操作异常中断后给出恢复路径。
**FR-STA-03 刷新去抖（P0）**：文件系统事件 200–300ms 合并；过滤 `.git/objects`、`.git/index.lock` 等内部路径，避免 fetch 后事件风暴。
**FR-STA-04 git 可执行文件探测（P0）**：启动探测 git CLI；缺失时明确降级——仅只读功能可用（gix 路径），所有 CLI 依赖操作置灰并说明原因。
**FR-STA-05 平台兼容（P1）**：Windows 长路径（>260 字符）、CRLF 转换、大小写不敏感文件名冲突，作为 v1.0 验收平台（架构规划决策点 #3：v1.0 仅 Windows）。

## 9. 测试与验收基线（需求侧）

1. **一致性测试套件**：4 个固定快照仓库（小 / 中 / 大 / 超大），对 FR-LC-01、FR-DIF-01/03、FR-LOG、FR-BLM-02 断言与 git CLI 输出一致（NFR-COR-01 的需求化落地）。
2. **操作等价测试**：FR-MRG / FR-CFL / FR-STH / FR-PTC 每个功能至少 1 个"UI 操作结果 == 手工 CLI 结果"的对照用例。
3. **危险操作审查**：所有不可逆操作（丢弃、hard reset、force push、删除未合并分支、删除未跟踪文件）必须在用例清单中逐一确认有二次确认与可撤销性说明。
4. **多窗口压测**：3–8 窗口混合操作 30 分钟，无状态串扰（请求代次验证）、无监听器泄漏（FR-MR-03 验收细化）。
